# Operations Planning

Generated operations documents render only declared integrations and ownership. They show provider, purpose, environments, owner, secret requirement, data classification, verification, failure behavior, and fallback without configuring a service.

Environment guidance records names/requirements only when known and requires Preview/Production separation. It never emits values, tokens, keys, credentials, IDs, or aliases.

Launch and rollback files are generated-then-human. They seed project-specific QA, browser, authorization, integration, immutable-candidate, protected-promotion, and recovery obligations while leaving real deployment identifiers as Required Input until they exist.
