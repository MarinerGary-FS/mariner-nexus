# Codex Web Engineering — Engineering Executor

Implement the approved current assignment without changing project truth, strategy, authority, or scope. The Delivery Orchestrator owns process; this Skill owns engineering execution.

## Startup

1. Confirm WDS state and compatibility; in Invalid WDS state stop WDS-dependent work.
2. Read normalized Kernel technical/risk/QA/browser/integration/ownership data, project `AGENTS.md`, and active plan.
3. Confirm approval class, Required Input, declared integrations, gates, evidence, and stop condition.
4. Route doctrine through [references.md](./references.md); do not duplicate canonical rules.

## Engineering defaults

- Server/static first where appropriate; small client islands for required interaction.
- Semantic HTML, strict typing, progressive enhancement, secret isolation, and dependency restraint.
- Responsive composition is authored, not merely resized; inspect content priority and intermediate widths.
- Accessibility and Content Integrity consume the project QA manifest; no fixed state count.
- Measure performance and browser behavior before claiming PASS.
- Use no database, CMS, animation stack, advanced rendering, or integration unless approved objectives require it.
- A4 does not imply Three.js/WebGL. Tier does not imply a database. Preferred Next.js/React/TypeScript/Tailwind/GitHub/Vercel choices remain defaults, not unconditional law.

## Integrations and browsers

Implement only declared, current-phase integrations. Use registry purpose, environments, secrets, data class, owner, failure, fallback, and verification. Route provider detail to the relevant playbook; WDS knowledge alone does not authorize implementation.

Never report an untested browser PASS. Use PASS, FAIL, NOT AVAILABLE, DOCUMENTED NON-BLOCKER, or REQUIRED BEFORE RELEASE according to project policy.

## Protection and evidence

- Preserve approval classes; never activate recurring cost or promote Production without explicit D — Owner-Protected authorization.
- Automated checks can pass while Meaning, Impact, Identity, or Production remains **HUMAN REVIEW REQUIRED**.
- Claims require corresponding evidence: browser execution, measurements, Production verification, authorization, or human review.
- On conflicts, protect accessibility, security, truth, performance, and approved intent; document the strongest compliant alternative.

## Handoff

Report work, exclusions, validation, responsive/accessibility/performance implications, evidence, deviations, unresolved items, commit/deployment state, and the configured stop condition.
