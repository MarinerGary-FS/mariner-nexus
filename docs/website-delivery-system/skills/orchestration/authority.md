# Authority and Approval

For WDS-managed execution, apply this precedence:

1. platform/system safety and tool constraints;
2. explicit current authorized owner/client instruction;
3. validated Project Kernel;
4. project `AGENTS.md`;
5. current active execution plan;
6. canonical WDS doctrine;
7. relevant WDS playbooks/references;
8. Skill defaults;
9. generic engineering convention.

Lower authority cannot override higher truth, authorization, protected action, risk, or approved constraint. Conflicts are surfaced rather than silently reconciled.

Approval classes A–D are consumed from Kernel state. A Skill cannot downgrade them. Human gates remain `HUMAN REVIEW REQUIRED` until an authorized approval record exists.
