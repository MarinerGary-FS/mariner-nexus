# Phase 05 — Systems Layer + Experience → Systems Deconstruction

## Status

Active. Phase 04C is committed, pushed, synchronized at `0/0`, and archived independently.

## Phase objective

Create the operational Node / Connection / Flow / State grammar and use it to reveal the truthful systems path behind a polished inquiry interaction.

## Why this exists

The visitor has seen visual craft and project proof. Phase 05 must now demonstrate that Mariner Nexus also understands the connected operation behind an interface, producing the recognition: “This isn’t just a design studio.”

## In scope

- Reusable semantic Node, Connection, Flow, State, and Signal grammar.
- Homepage Experience → Systems Deconstruction between existing capability/proof language and Approach reassurance.
- Truthful representative flow: inquiry interaction → validation → structured Google Workspace record → notification → human follow-up.
- Gradual light → Silver → Structural Gray → Graphite → Nexus Black environmental descent.
- Keyboard-selectable flow nodes and active path enhancement.
- Static-first Capabilities Systems disclosure using the same grammar.
- Thread → Connection → Flow evolution using Phase 04C semantics.
- Desktop spatial, tablet intermediate, mobile sequential, and reduced-motion choreography.

## Out of scope

- Live inquiry persistence, Google Workspace credentials/integration, custom backend, CRM/database, AI orchestration, authentication, portal/dashboard product, full Nexus, canvas, Three.js/WebGL/WebGPU, GSAP, graph/diagram library, new case studies, or service-scope expansion.

## Required user experience

- A polished inquiry surface appears first and remains clearly representative rather than submitting data.
- The visible interaction gives way to an understandable operational sequence.
- Every node names an entity; every connection is explained by ordered semantic content.
- Selecting/focusing a stage emphasizes its related path and concise business purpose without being required for comprehension.
- The signature line “The experience shouldn’t stop when someone clicks Submit.” lands with minimal surrounding copy.
- The existing navigation context transitions calmly into Systems and returns toward Approach.

## Technical requirements

- Server-render all headings, copy, semantic process structure, and static system state.
- Use one route-local Client Component for Observer reveal and native node selection.
- Use CSS custom properties and semantic DOM; no SVG is required for the linear truthful flow.
- Capabilities disclosure remains server-rendered and native (`details`) with no extra client island.
- No new dependency, scroll listener, render loop, request, or delayed content.

## Mobile requirements

- Replace desktop spatial flow with a vertical Experience → Submit → Validate → Capture → Notify → Act sequence.
- Maintain full content and selection access with 44px+ targets and readable dark contrast.
- Do not compress or horizontally scroll a desktop graph.

## Accessibility requirements

- Native buttons use `aria-pressed` and expose stage names/purpose.
- One ordered list preserves meaningful reading order and static comprehension.
- Focus retains the 2px SIGNAL outline/4px offset and is distinct from active path state.
- Active state uses number, label, status text, and geometry in addition to color.
- Reduced motion presents the same states immediately; no essential relationship exists only in lines.
- Representative inquiry controls are non-submitting and clearly labeled as demonstration.

## Performance requirements

- Minimal homepage-only client-JS increase.
- No blocking media, layout shift, animation runtime, large SVG, graph package, or preload.
- Content is ready when scrolled into view; Observer only changes enhancement state.

## Acceptance criteria

1. Nontechnical visitors can explain what happens after Submit.
2. Technical visitors see a genuine, scoped operational relationship.
3. Node, Connection, Flow, State, Thread, and Signal remain one coherent grammar.
4. Environmental descent feels gradual and dark contrast passes.
5. Signature line remains visually decisive and uncluttered.
6. Homepage and Capabilities stay understandable without JavaScript.
7. Desktop, tablet, and mobile use intentional distinct choreography.
8. Reduced-motion users lose no information.
9. Phase 04A–04C systems remain intact and performance stays strong.
10. No unimplemented or out-of-scope capability is claimed as live.
