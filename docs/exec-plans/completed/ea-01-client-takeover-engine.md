# Experience Amplification 01 — Client Takeover Engine

## Objective

Turn the approved client-identity boundary into a reusable, staged experience engine and prove it with the authorized Undugu transformation record. Preserve the Mariner shell and every production system outside the client boundary.

## Locked scope

- Extend the project schema with a typed experience profile covering typography, spacing, surfaces, media scale, CTA geometry, transition timing, and takeover intensity.
- Establish six deterministic states: Mariner, Introduction, Influence, Takeover, Release, and Return.
- Amplify the Undugu pressure point on `/work` and the full experience on `/work/undugu`.
- Keep header, footer, routing, inquiry, SEO, analytics, and operational integrations unchanged.
- Use only authorized Undugu media and existing font infrastructure.
- Preserve semantic HTML and readable static client styling when JavaScript or motion is unavailable.

## Acceptance

- The takeover changes the visual grammar, not only the palette.
- Undugu is clearly felt before entry, dominates its record, and yields cleanly back to Mariner.
- Desktop, tablet, mobile, and reduced-motion states remain usable and coherent.
- No new runtime dependency or unauthorized project is introduced.
- Standard validation, visual evidence, performance impact notes, and a completion report are produced.
