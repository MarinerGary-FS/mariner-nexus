# Mariner Nexus Client Project Bootstrap

Use this file when starting a new client repository with the reusable Website Delivery and Codex Web Engineering skills.

## Required project-specific specification

Create `docs/project-spec/` with:

1. `01-client-truth.md`
2. `02-scope-architecture.md`
3. `03-audience-architecture.md`
4. `04-information-architecture.md`
5. `05-experience-architecture.md`
6. `06-visual-system.md`
7. `07-signature-interactions.md`
8. `08-technical-architecture.md`
9. `decisions.md`

Create:
- `docs/exec-plans/active/`
- `docs/exec-plans/completed/`

## Discovery acceleration rule

Reuse the workflow, schemas, scope classification, QA gates, and technical defaults.

Do **not** reuse:
- Mariner Nexus palette,
- Mariner Nexus typography,
- Mineral Teal,
- Nexus interaction,
- client takeover behavior,
- project-specific copy,
unless the new client specification independently calls for them.

## Required starting questions

- What is the client trying to create, evolve, or transform?
- What exists today?
- Who is the audience?
- What should visitors understand, feel, and do?
- What happens after each primary action?
- What systems already exist?
- What operational burden is acceptable after launch?
- What does the client consider high quality?
- What should this experience never feel like?
- What is CORE, SCOPED, and OUT for this engagement?

The client does not need to arrive with the solution figured out.
