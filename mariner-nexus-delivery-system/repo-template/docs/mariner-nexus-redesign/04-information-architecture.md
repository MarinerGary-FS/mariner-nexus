# 04 — Information Architecture

## Principle

> Simple navigation. Deep experience.

Exploration should reveal increasingly sophisticated Mariner Nexus capabilities.

## Primary navigation

- Capabilities
- Work
- Approach
- Company
- Start a Project

## Routes

- `/`
- `/capabilities`
- `/work`
- `/work/[project]`
- `/approach`
- `/company`
- `/start`
- `/privacy`
- `/terms`

No generic `/contact`.
No pricing page.
No industries page.
No public AI page.
No Lab at launch.

## Approach

Answers:
> What does working with Mariner Nexus look like for me?

Conceptual sequence:
Understand → Define → Architect → Create → Connect → Refine → Launch → Evolve.

## Start a Project

The `/start` experience is the beginning of client acquisition, not a generic contact form.

Ask about:
- what they are trying to create/change,
- current state,
- success definition,
- existing presence,
- references,
- timeline,
- contact details.

Do not ask the prospect to choose a technical service or package.

## V1 inquiry persistence

`/start` → secure server endpoint → Google Workspace record → email notification → human review.

Google Workspace record is source of truth. Email is notification.

## Footer

Connect:
- Email only.

No public GitHub.

## Navigation behavior

Contextual white-glove navigation subtly communicates where the visitor is in the experience without becoming a loud progress meter.
