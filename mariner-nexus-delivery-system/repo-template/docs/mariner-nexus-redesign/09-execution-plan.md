# 09 — Codex Execution System

## Mission

The redesign has already been designed.

Codex's responsibility is to engineer it faithfully while protecting performance, accessibility, maintainability, security, and the approved strategic intent.

## Persistent knowledge

- Keep `AGENTS.md` concise.
- Keep deeper product truth in this documentation directory.
- Keep active execution plans under `docs/exec-plans/active/`.
- Move completed plans to `docs/exec-plans/completed/`.
- Record material decisions in `decisions.md`.

## Decision authority

### Level 0
Pure implementation detail. Codex may decide freely.

### Level 1
Implement visible/architectural behavior within the approved intent.

### Level 2
Propose before material architectural change:
- major dependency,
- CMS,
- database,
- auth,
- GSAP,
- Three.js,
- inquiry architecture,
- content schema.

### Level 3
Never silently change:
- positioning,
- service scope,
- navigation,
- pricing model,
- AI positioning,
- acquisition strategy,
- visual doctrine,
- approved signature purpose.

## Agent roles

### Architect
Reads specification and prepares bounded implementation plan.

### Builder
Implements only the approved task.

### Design Reviewer
Reviews hierarchy, rhythm, responsiveness, motion, and adherence to the visual/experience system.

### Engineering Reviewer
Reviews server/client boundaries, architecture, dependencies, accessibility, performance, security, and maintainability.

### QA
Tests actual behavior and failure states.

Use parallel agents/worktrees only when independence or comparative alternatives provide real value.

## Phase gates

### Gate A — Foundation
Reaction:
> This is a serious company.

### Gate B — Corporate Core
The company, audience, and proposition are understandable without advanced effects.

### Gate C — Work
The final work demonstrates quality and leads into transformation stories/live proof.

### Gate D — Experience
Adaptability is experienced rather than claimed.

### Gate E — Systems
Reaction:
> They're not just a design studio.

### Gate F — Nexus
The flagship interaction explains solution-specific adaptability and produces the intended surprise.

### Gate G — Final
The visitor should leave asking:
> What could Mariner Nexus do with mine?

## Rules

- No silent compromises.
- No drive-by refactors.
- Every dependency earns its place.
- Feature freeze during hardening.
- Codex does not invent final strategic copy.
- If implementation and strategy conflict, surface the conflict.
- If scope is ambiguous, do less.
- If performance/accessibility conflict with spectacle, protect performance/accessibility.

## Definition of done

Functional + intentional + responsive + accessible + performant + maintainable + validated + materially documented.
